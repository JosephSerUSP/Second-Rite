### Experiment

C003 — Breakout With Moving Bricks

### Result

complete

### Authored Surface

Authored scene `c003_moving_breakout.json` and a small `SCRIPT` section for brick management. The `on_enter` and `on_select` hooks initialize variables and state without requiring duplicate initialization files. Declarative formulas manage most movement and bounce handling.

### SCRIPT / Native Escape Hatches

The `init_bricks` and `update_bricks` routines were implemented as `SCRIPT` blocks within the JSON configuration. This is necessary because Thestra Engine Event Programs and Formulas cannot currently materialize populated collection values, mutate an authored collection by index, or iterate an arbitrary authored collection without escaping into Lua `SCRIPT`.

### Missing Reusable Semantics

The engine lacks a reusable command to define and mutate collections of identical interactive entities natively through declarative commands (such as a `FOR_EACH` array iteration or bulk-updating properties).

### Awkward But Expressible

Handling array logic directly inside `SCRIPT` tags inline in the JSON block works, but it places arbitrary logic and variables loosely into JSON string contexts which bypasses tooling syntax checks. However, boolean literals (`true`/`false`) and formula expressions handle basic game state smoothly without needing string comparisons.

### Tooling / Discoverability Gaps

There is no strong type checking or linting within the JSON's inline `SCRIPT` blocks, making debugging collection-based state more cumbersome for an author.

### Backend Leakage

None. The movement loop and variables run on standard Lua tables and core engine facilities.

### Project Leakage

Isolated entirely to the benchmark framework, no dependency on Second Gate logic.

### Author Legibility

A competent RPG Maker-style author would understand the overarching flow but might find the inline raw script array iteration for bricks less approachable compared to typical RPG Maker custom action blocks.

### Reusable Successes

The collision and bounding box calculations remain simple thanks to the discrete frame loop step setup in the Thestra scene. The `v.time.dt` namespace variable works beautifully alongside fixed frame updates without raw script. Dynamic UI window layouts evaluated automatically via formulas keep positioning logical and clean.

### Architecture Recommendation

candidate reusable semantic gap
