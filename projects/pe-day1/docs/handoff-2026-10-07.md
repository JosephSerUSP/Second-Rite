## How to build, test and run

- **Generator:** `python projects/pe-day1/tools/chapter/build_chapter.py`
  writes `data/scenes/day1_*.json` from `tools/chapter/rooms.json`. Never
  hand-edit the scenes. The menu lives in `tools/chapter/menu.py`.
- **Rooms:** `author_rooms.py` (Blender) then `bake_rooms.py` (Second Gate
  pipeline). Set `BLENDER_EXECUTABLE` to Blender 5.2. `author_rooms.py` refuses
  to overwrite an existing room without `--force`.
- **Models:**
  - Characters: `build_aya.py`, `build_bosses.py` (they use `--export-only`
    once a `.blend` exists).
  - Skins: `build_windowskin.py`.
- **Unit gate:** stage with `node tools/ci/stage-project-gates.js --output <g>`,
  then `powershell -ExecutionPolicy Bypass -File tools/ci/run-staged-unit.ps1 -GameRoot <g>`.
  It must print `ALL UNIT TESTS OK`. A run takes about 4–6 minutes.
- **Validation:** stage the project with
  `node -e "console.log(require('./studio/editor/project-play').stageProject({installRoot:process.cwd(),projectRoot:require('path').resolve('projects/pe-day1')}))"`,
  then run `lovec . validate` in the printed directory.
- **G4:** `tools/golden/check-state.ps1`. Regenerate with `capture-state.ps1`
  when `engine.json` changes.
- **Previews:** `lovec . preview-scene <id>` returns base64 PNG JSON. The
  private helpers I used are in my scratchpad and are not committed. Pin
  `sceneState` values in a staged `data/scenes.json` copy to capture menu or
  battle states.
- **Main test:** `tests/test_pe_day1_chapter.lua` (174 checks) walks all 18
  rooms. It covers controls, the menu, progression, capacity, and honest Club
  fights.

## State of the slice

- **Chapter:** 18 rooms following the original Day 1 route, from the entrance
  to the street. Locks, pickups, and fights against Melissa, rats, Eve and the
  alligator. All rooms are baked with Second Gate lighting.
- **Cameras:** fixed per-room views composed from named original shots, with
  cuts on thresholds. There are no moving cameras. The engine's scene camera
  has a `frame` (plate) whose window scrolls, as pre-rendered games do.
- **Controls:** screen-relative movement, with the direction latched across
  camera cuts.
- **Characters:** Aya is redesigned with an 8-frame run; the bosses are
  authored models with idle and wind-up poses.
- **Progression:**
  - Stat tracks: Offense, Defense, PEnergy, Status Recover, Active Time and
    Item Capacity.
  - EXP: 3 to reach level 2.
  - Bonus Points per fight, minus 10% per hit taken.
  - Level-ups raise the tracks; 100 BP buy a level of Active Time or Item
    Capacity.
  - Active Time speeds the AT gauge; PEnergy speeds PE recovery.
- **Inventory:** every carried thing takes a slot. Capacity is 9 + Item
  Capacity, and a full inventory refuses pickups. Items are named as in the
  original: M84F, Club, N Vest, N Protector, Ammo Crate, Rehearse Key.
- **Menu (B):** the original's structure. A title bar shows the help text and
  the play-time clock. An icon column switches between Item, PE, Weapon, Armor
  and BP over the status screen. HP and the PE bar sit at the bottom right.
  The panels use hollow bevelled frames over a full-screen PS1 subtractive
  darken.

## Traps

- Bash heredocs eat `\\` sequences. Write patch scripts to files.
- `sed -i` converts CRLF to LF.
- The unit runner can exceed the Bash tool's 10-minute limit. Use a 580 s
  timeout or run it in the background.
- Window text `{formula}`s fail silently as `0`. The chapter test now parses
  them all, so keep that check.
- Formulas shared by allies and enemies (the AT rate) need every unit to
  declare the parameter. Enemies declare `act: 1`.
- The test fixture swaps the pe-day1 data and the EXP curve into the shared
  loader. Its `ctx.party` must stay the session's party.
