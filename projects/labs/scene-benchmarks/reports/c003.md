### Experiment

C003 — Breakout With Moving Bricks

### Result

complete

### Authored Surface

Authored scene `c003_moving_breakout.json` and a small modified script section. The changes included moving logic in the `update_bricks` script to iterate over active bricks and reverse horizontal direction on edge collision, as well as advancing vertically when edge collision happens (similar to Space Invaders movement pattern).

### SCRIPT / Native Escape Hatches

The `init_bricks` and `update_bricks` routines were implemented as SCRIPT blocks within the JSON configuration. This is necessary because Thestra doesn't currently provide high-level abstractions for arrays of similar active objects (like bricks) directly mapped to an engine-managed collection system within the Scene file.

### Missing Reusable Semantics

No built-in way to define and mutate collections of identical interactive entities solely through declarative commands (like iterating or bulk-updating properties).

### Awkward But Expressible

Handling array logic directly inside SCRIPT tags inline in the JSON block works, but it puts arbitrary logic and variables loosely into JSON string contexts which bypasses tooling syntax checks.

### Tooling / Discoverability Gaps

No strong type checking or linting within the JSON's inline `SCRIPT` blocks, making debugging brick state more cumbersome for an author.

### Backend Leakage

None immediately apparent; the movement loop and variables run on top of standard Lua and basic table usage.

### Project Leakage

Isolated entirely to the benchmark framework, no dependency on Second Gate logic.

### Author Legibility

A competent RPG Maker-style author would understand the overarching flow but might find the inline raw script array iteration less approachable compared to typical RPG Maker custom action blocks.

### Reusable Successes

The collision and bounding box calculations remain simple thanks to the discrete frame loop step setup in the Thestra scene. `v.time.dt` works beautifully alongside fixed frame updates.

### Architecture Recommendation

candidate reusable semantic gap: Engine-level collections / loops across collections natively within Scene structures would be a significant authoring improvement over Lua SCRIPT arrays.
